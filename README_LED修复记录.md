# WS2812 状态灯修复记录（2026-11-11）

> 这一页是**踩坑记录 + 结论**，以后再动灯之前先读一遍。
> 结论先说：**这块板的灯是标准 WS2812B / GRB 顺序，硬件一直是好的。
> 之前所有"颜色对不上"都是驱动代码的 bug，两个，都在我们这边。**

---

## 1. 最终结论（可以直接依赖的事实）

| 项目 | 事实 | 怎么确认的 |
|---|---|---|
| 灯型号 | 标准 WS2812B 类，单像素 | 只点亮一个字节时只亮一种颜色 |
| 颜色顺序 | **GRB**（先绿、再红、再蓝） | 逐字节测试：第2字节=纯红、第3字节=纯蓝 → 第1字节必为绿 |
| 像素数 | 1 个（第 4 个字节无反应） | 试到第 4 个位置时灯全灭 |
| 红色观感 | 亮度低时是正红，亮度高时偏橙 | 同一个通道，40/255 显红、255 显橙 |
| 数据线 | PA7（原 SPI6_MOSI） | — |
| 驱动方式 | **已改为 DWT 周期计数 bit-bang**，不再用 SPI | — |

## 2. 两个真正的 bug

### bug ①：少发比特，靠残留位补齐 → 出现"不可能的颜色"

**现象**：只点亮第 0 个字节时，灯显示黄色（红+绿一起亮）。单个字节不可能点亮两个通道。

**原因**：WS2812 **必须收到完整的 24 位**才会锁存。测试函数当时只发了 8 位（或 16 位）就拉低复位，
剩下没发的位保留在芯片的移位寄存器里 —— **它们是上一帧的残留数据**，于是两帧的颜色混在一起。

**规则**：任何一次发送都必须是完整帧（3 通道 = 24 位，4 通道 = 32 位）。
绝对不能"只发改动的那一个字节"。

### bug ②：SPI 编出来的时序太临界

**现象**：颜色随机不对、时好时坏。

**原因**：用 SPI 模拟 WS2812（1 个灯位 = 3 个 SPI 位）时，脉冲宽度由 SPI 时钟决定：

| | T0H | T1H | 周期 |
|---|---|---|---|
| WS2812B 规格 | 0.40 µs ±150 ns | 0.80 µs ±150 ns | 1.25 µs |
| SPI 2.148 MHz（晶振 25 MHz） | 0.465 µs | **0.930 µs** | 1.39 µs |
| SPI 2.062 MHz（晶振 24 MHz） | 0.485 µs | **0.970 µs 超规格** | 1.45 µs |

T1H 离 950 ns 上限只剩 20 ns 余量，晶振一偏就超规格，灯开始误判比特。
**而这块板的晶振到底是 24 还是 25 MHz 至今没确认**（厂家资料写 24 MHz，工程里写 25 MHz）。

**修复**：改成 DWT 循环计数 bit-bang，时序由 `SystemCoreClock` 现算：

```
T0H = 0.40 µs    T1H = 0.80 µs    周期 = 1.25 µs
```

晶振误差 4% 只造成 16 ns 偏差，影响可以忽略。

### 顺带修掉的 bug ③：一个周期发两帧

调试期间我加过"SWD 强制颜色"和"通道测试"，它们和正常状态灯逻辑**各发一帧**，
两帧只隔几十微秒，灯把它们当成一帧解 → 又是一种混色来源。

**规则**：每 50 ms 周期**只准发一帧**。现在代码里用 `if (g_led_channel_test) ... else ...`
保证互斥。

## 3. 现在代码里留下的调试工具（以后直接用，别再重写）

| 工具 | 用法 |
|---|---|
| `g_led_test_enable` = 1 | 用 `g_led_test_r/g/b`（0~255，不受亮度倍数影响）强制显示颜色，SWD 改一个数立刻生效 |
| `g_led_test_r/g/b` | 三个通道原始值 |
| `g_led_channel_test` = 1 | 用 SWA+SWB 选"只点亮第 0/1/2/3 个字节"，用来验证通道顺序 |
| `g_led_ok` / `g_led_fail` | 发送计数，`fail` 一直涨说明发送链路有问题 |
| `g_led_r/g/g/b` | 最后一帧实际请求的三个通道值 |

SWD 读写示例（地址以当前编译产物为准，用 `arm-none-eabi-nm` 查）：

```powershell
& $ocd ... -c "init" -c "halt" -c "mww 0x24000004 255" -c "resume" -c "shutdown"
```

## 4. 以后改灯必须遵守的四条

1. **永远发完整帧**（24 位 / 32 位），不允许发半帧。
2. **每个 50 ms 周期只发一帧**，调色/测试代码必须和正常逻辑互斥。
3. **不要用 SPI 编 WS2812 时序**，除非能确认 `SystemCoreClock` 和晶振一致。用 bit-bang。
4. **判断颜色前先确认亮度**：这颗灯红色在满亮度下就是偏橙，别据此判断"通道错了"。

## 5. 之前的错误结论（作废，别再引用）

| 曾经的结论 | 实际情况 |
|---|---|
| "这块板是 RGB 顺序，要改 `CHASSIS_LED_ORDER=1`" | 错。是 GRB，`=0` 才对 |
| "FDCAN3 那一路没有收发器" | 错。收发器是好的，是**复用功能号**配错了（AF2 → AF5） |
| "灯的红/蓝芯片可能坏了" | 错。硬件完好 |
| "红被显示成绿 = R/G 反了" | 错。是被 bug ③ 的双帧混色骗了 |
